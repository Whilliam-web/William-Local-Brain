# Whiliam 个人知识库说明

这个仓库是 Whiliam 的个人 Obsidian 知识库，用来承接项目工作、长期跟踪、自我成长、日常知识积累、个人认识论、工作模板，以及和各类 AI 智能体协作后确认保留的成果。

智能体运行过程与正式知识分开保存：草稿、预览、日志和候选成果默认进入 `D:\AI Workspaces`，软件代码进入独立 Git 仓库；只有确认后的正式成果和必要决策记录写回本知识库。

这个知识库的目标不是“收藏更多资料”，而是把原始信息逐步加工成：

- 可以推进的行动
- 可以复用的知识
- 可以支撑判断的材料
- 可以沉淀的方法
- 可以长期跟踪的领域
- 可以反复使用的模板
- 更顺手的人机协作方式

## 核心原则

按照信息当前在我生活和工作中的作用来组织，而不是单纯按照主题分类。

整理任何材料时，先判断它属于哪一种状态：

- 它是还没有处理过的信息吗？
- 它属于我正在做的项目或任务吗？
- 它属于我希望长期跟踪和投入的领域吗？
- 它是以后可以反复调用的知识吗？
- 它是我的认识论、世界观、判断框架或做事原则吗？
- 它是可以复用的工作模板吗？
- 它已经完成、暂停、过期或不再活跃了吗？

如果暂时判断不清，就先放在 `00收件箱/`，并标明需要确认的问题。

## 目录含义

### `00收件箱/`

放临时捕捉、下载文件、粗糙想法、还没判断用途的信息。

这个目录是“未处理区”，不是最终归宿。处理收件箱时，需要判断每个东西应该进入项目、长期领域、知识积累、心法、模板、归档，还是继续留在收件箱等待确认。

### `01三两的打工tasks/`

放正在推进的具体项目、工作任务、调研任务、交付物，以及任何需要产出成果的事情。

项目比较复杂时，优先使用这个结构：

```text
项目名称/
  需求确定/
  搜集信息/
  方案/
  反馈/
  工作记录.md
```

小任务不需要强行套完整结构。但只要一个项目涉及多轮信息对齐、资料搜集、成果产出和反馈复盘，就优先用这套结构。

### `02深耕领域/`

放我希望长期跟踪、长期投入、长期培养关系的领域。

这里不是普通资源区，而是“长期注意力对象”。它可以是健身、身体管理、审美、长期技能、个人成长主题，也可以是任何我希望持续观察、持续投入、持续迭代的方向。

### `03百宝箱/`

放日常知识积累和以后可能反复调用的东西。

这里是“可复用知识仓库”，不是杂物箱。放进来的内容最好说明它为什么有用、未来可以怎么复用。

### `04深埋于地的宝藏/`

放已经完成、暂停、过期、不再活跃，但未来可能还值得搜索和复用的内容。

归档不是删除。开始类似项目之前，应该先搜索这里，看看以前是否已经有材料、判断、模板或经验可以复用。

### `05心法/`

放我的认识论、世界观、判断框架、做事原则和深度反思。

这里不是原始资料区，而是“消化之后的理解”。一篇好的心法笔记，应该能帮助我以后更好地思考、判断、感知和行动。

### `06模版/`

放可复用的模板和规范化工作格式。

只要一件事会重复发生，就应该考虑把它沉淀成模板。

## 灵感和 idea 的处理方式

灵感和 idea 最开始可以进入 `00收件箱/`。

初步处理之后，按照它的性质流向不同目录：

- 如果它变成一件要推进的事，进入或链接到 `01三两的打工tasks/`。
- 如果它属于一个长期关注领域，进入或链接到 `02深耕领域/`。
- 如果它变成可复用知识，进入或链接到 `03百宝箱/`。
- 如果它变成个人原则、判断框架或世界观，进入或链接到 `05心法/`。
- 如果它变成可复用格式，进入或链接到 `06模版/`。
- 如果它暂时不活跃但以后可能有价值，进入 `04深埋于地的宝藏/`。

如果以后新增专门的灵感空间，优先使用：

```text
07灵感池/
```

`07灵感池/` 适合放那些已经不算纯收件箱碎片、但还没有成熟到成为项目、知识、模板或心法的想法。

## 项目处理模式

对于活跃项目，优先按照这个流程工作：

```text
需求确定 -> 搜集信息 -> 方案 -> 反馈
```

### 1. 需求确定

先明确真正的需求。

需要判断这个项目主要服务于什么：

- 我的个人成长
- 当前工作需要
- 长期学习
- 项目评估
- 孵化或投资判断
- 其他具体目标

这个阶段要对齐：我们到底要产出什么？这个成果要支持什么判断、行动或决策？

### 2. 搜集信息

围绕已经确认的需求，搜集和整理相关信息。

这个阶段要区分：

- 事实
- 假设
- 推论
- 风险
- 缺失信息
- 来源可靠性

搜集信息的目的不是堆资料，而是判断这件事是否可行、是否有价值、是否值得继续推进。

### 3. 方案

基于已经对齐的需求和已经整理的信息，产出方案、备忘录、报告、计划或其他具体成果。

在这个仓库里，`方案` 指的是：我和智能体对齐信息与需求之后，产出的可用成果。

### 4. 反馈

成果被使用之后，要收集反馈，并把反馈沉淀成可复用经验。

有价值的反馈可以沉淀到：

- 当前项目文件夹
- `工作记录.md`
- `05心法/`
- `06模版/`
- `03百宝箱/`
- 如果项目完成或不活跃，进入 `04深埋于地的宝藏/`

## 工作记录

有连续性的项目，建议维护：

```text
工作记录.md
```

工作记录可以包括：

- 日期
- 做了什么
- 当前判断
- 待确认问题
- 收到的反馈
- 下一步行动
- 相关输出和资料链接

`工作记录.md` 是项目过程、反馈和后续复用之间的连接层。

## 和智能体的关系

`99系统/知识库介绍.md` 是这个知识库的说明，写给人看。

`AGENTS.md` 是智能体的工作规范，写给接入这个仓库的 AI 助手、编程智能体和自动化工具看。它应该更短、更明确，告诉智能体在这个仓库里如何判断、如何处理、什么时候需要确认，以及如何产出可复用内容。

`whiliam-vault-workflow` 是任务路由层，负责判断任务属于知识整理、项目研究、视觉讨论、软件开发还是知识库维护，并把过程材料送到正确位置。

具体协作边界见 [[本地知识库与智能体协作规范]]。

恢复项目时先看 [[项目记忆索引]]；判断人、智能体、过程文件和代码的边界时看 [[人机工作内容与记忆分层]]；查找 2026-08-01 前的旧过程路径时看 [[过程文件迁移索引]]。

这个知识库应该随着使用越来越好用：把原始信息变成行动、长期跟踪、可复用知识、个人判断、工作模板，以及我和各类智能体之间越来越顺手的协作方式。
