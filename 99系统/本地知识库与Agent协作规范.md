# 本地知识库与智能体协作设计

> 更新日期：2026-07-08  
> 目的：把这个 Obsidian vault 建设成一个可长期积累、可被多种智能体协作维护的本地知识库。

>**这是所有部署在用户MS66，也就是这台设备上所有在 Whiliam 个人 Obsidian 知识库中的工作规范。**
## 1. 一句话定位

这个仓库是我的本地知识库，也是我与各类 AI 智能体协作的工作空间。  
它不仅用于保存笔记，还用于沉淀知识管理规则、智能体使用方式、自动化流程和个人工作系统。

## 2. 这个知识库要解决什么问题

我希望这个 vault 能同时承担三类任务：

1. **知识管理**
   - 保存想法、资料、摘录、项目笔记和长期知识。
   - 把零散信息整理成结构化、可复用、可检索的 Markdown 笔记。
   - 通过 Obsidian 双链、标签、索引页和模板建立个人知识网络。

2. **智能体协作**
   - 让接入这个仓库的各类智能体都能理解 vault 的结构和规则。
   - 让智能体帮我创建、整理、改写、归档和审查笔记。
   - 把高频任务沉淀为稳定流程，而不是每次重新说明。
   - 构建属于智能体的长期记忆体系和更新模式

3. **个人工作流建设**
   - 把学习、写作、研究、项目管理和资料整理放进同一个系统。
   - 让本地文件既适合人阅读，也适合智能体自动处理。
   - 逐步建立属于自己的“第二大脑 + 智能体工作台”。

## 3. 基本原则

### 3.1 Obsidian 优先
- 所有笔记尽量使用标准 Markdown。
- 内部链接优先使用 Wiki-link，例如 `[[笔记名]]`。
- 图片、附件和资料尽量保存在 vault 内，避免依赖外部临时链接。
- 重要主题应有入口页或索引页，避免知识散落。

### 3.2 本地优先

- 这个 vault 是本地知识资产，优先保证可离线阅读、可迁移、可备份。
- 外部工具可以辅助处理，但核心内容应沉淀为本地 Markdown 文件。
- 不把长期知识只留在聊天记录、网页收藏或临时文件中。

### 3.3 智能体友好

- 文件命名、目录结构、模板和标签应尽量清晰。
- 高频任务应写成明确流程，方便不同智能体重复执行。
- 对批量修改、删除、重命名等高风险操作，智能体应先说明计划再执行。
- 重要笔记应包含足够上下文，避免只有碎片化摘录。

### 3.4 渐进建设

- 不追求一次性设计完美系统。
- 先建立少量稳定规则，再根据真实使用逐步演化。
- 当某个流程重复出现多次，再考虑沉淀为模板、Skill、脚本或插件。

## 4. 智能体在这个 vault 中的角色

### 4.1 笔记整理助手

智能体可以帮助我：

- 把零散文本整理成结构化笔记。
- 为笔记补充标题、摘要、标签和相关链接。
- 把临时想法改写成长期可读的知识卡片。
- 合并重复主题，拆分过长笔记。

### 4.2 知识库维护助手

智能体可以定期检查：

- 是否存在孤立笔记。
- 是否存在断链或错误链接。
- 是否存在重复标题、重复主题或空笔记。
- 是否需要新增索引页、目录页或主题入口。

### 4.3 项目与研究助手

智能体可以协助：

- 为项目建立任务页、资料页和决策记录。
- 从资料中提取研究问题、观点、证据和行动项。
- 把一个主题扩展为学习提纲、写作提纲或复习清单。
- 根据当前 vault 中的材料生成总结、路线图或计划。

### 4.4 自动化设计助手

当某个任务反复出现时，智能体可以帮助我把它沉淀为：

- 笔记模板
- `AGENTS.md` 规则
- 智能体 Skill / 工作流
- 本地脚本
- MCP / 插件集成
- 定期巡检或自动化工作流

## 5. 推荐的基础结构

这个 vault 可以逐步整理为以下结构：

```text
00.索引/
10.输入/
20.永久笔记/
30.项目/
40.领域/
50.资料/
90.模板/
99.附件/
```

各目录的作用：

- `00.索引/`：主题入口、MOC、导航页。
- `10.输入/`：临时收集的想法、摘录、网页内容、待处理材料。
- `20.永久笔记/`：经过整理、可以长期复用的知识卡片。
- `30.项目/`：有明确目标和结束条件的项目资料。
- `40.领域/`：长期关注但没有明确结束时间的领域。
- `50.资料/`：原始材料、引用来源、文献、网页摘录。
- `90.模板/`：固定格式的笔记模板。
- `99.附件/`：图片、PDF、音频、其他附件。

这只是初始建议，不需要一次性迁移全部文件。可以先从索引、模板和新笔记规范开始。

## 6. 建议创建的长期规则文件

### 6.1 `AGENTS.md`

`AGENTS.md` 用来告诉接入这个仓库的智能体：以后在这个 vault 里工作时应该遵守哪些长期规则。

建议包含：

- 这是一个 Obsidian vault。
- 文件引用使用 Wiki-link。
- 不随意删除、覆盖或批量迁移文件。
- 批量修改前先列计划。
- 新笔记应尽量包含标题、摘要、标签、相关链接。
- 输出给用户时，vault 文件用 `[[文件名]]` 格式。

### 6.2 模板文件

## 7. 可以沉淀的智能体工作流

### 7.1 笔记整理工作流

输入：一段零散文本、摘录或草稿。  
输出：结构化 Obsidian 笔记。

处理步骤：

1. 提炼标题。
2. 写一句话摘要。
3. 分解核心观点。
4. 补充标签。
5. 建议相关链接。
6. 标记未完成问题或后续行动。

### 7.2 Vault 巡检工作流

输入：整个 vault。  
输出：整理建议报告。

检查内容：

- 孤立笔记
- 断链
- 重复标题
- 空笔记
- 缺少索引的主题
- 附件未引用情况

### 7.3 主题索引生成工作流

输入：一个主题关键词。  
输出：一个 MOC / 主题入口页。

内容包括：

- 主题简介
- 相关笔记列表
- 子主题分类
- 关键问题
- 推荐阅读顺序
- 未来可补充内容

### 7.4 资料转永久笔记工作流

输入：网页、PDF、摘录、课堂材料或临时记录。  
输出：可长期复用的知识笔记。

要求：

- 不只是复制原文。
- 要提炼概念、论点、例子和可迁移启发。
- 保留必要来源信息。
- 尽量链接到已有笔记。

## 8. 后续建设路线图

### 第一阶段：建立基础规则

- 完成 [[本地知识库与Agent协作规范]] 作为顶层设计说明。
- 创建 `AGENTS.md`。
- 建立基础目录和模板。
- 建立知识库总览页。

### 第二阶段：整理已有内容

- 扫描现有笔记。
- 找出孤立文件、重复主题和未完成笔记。
- 为已有内容建立索引。
- 逐步把输入材料转化为永久笔记。

### 第三阶段：沉淀智能体工作流

- 把常用提示词整理成固定模板。
- 将重复流程转成智能体 Skill、工作流或脚本。
- 建立 vault 巡检、主题索引生成、资料归档等自动化流程。

### 第四阶段：接入更多工具

根据需要再考虑：

- Git / GitHub 版本管理
- 浏览器资料采集
- PDF / 图片 OCR
- Notion、飞书、Gmail 等外部系统
- MCP 或插件化集成
