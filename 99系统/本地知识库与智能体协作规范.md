# 本地知识库与智能体协作规范

> 更新日期：2026-08-01  
> 适用范围：`D:\Whiliam local brain` 及围绕它运行的本地智能体  
> 核心规则：正式知识、软件工程、智能体过程三者分区保存。

## 1. 定位

`D:\Whiliam local brain` 是 Whiliam 的正式 Obsidian 知识库，保存有效工作内容、研究材料、已确认方案、真实反馈、工作记录、可复用知识、模板和个人判断。

它不是通用软件开发仓库，也不承担智能体会话状态、浏览器测试日志、临时网页、依赖、构建缓存或未收尾 worktree 的长期存储。

## 2. 三层工作区

### 正式知识库

路径：`D:\Whiliam local brain`

保存用户认可的正式内容。Delta Space、Delta X 等业务内容本身属于有效工作，不因混有智能体过程文件而被整体移除。

### 独立代码仓库区

路径：`D:\Whiliam Projects`

保存网站、程序、自动化、测试和构建项目。现有嵌套代码仓库先保持原位并由根 `.gitignore` 排除，完成边界审计后再决定是否迁移。

### AI 临时工作区

路径：`D:\AI Workspaces`

```text
AI Workspaces/
├── Active/       正在执行
├── Review/       等待用户确认
├── Archive/      有期限保留的过程档案
└── WORKTREES.md  未关闭 worktree 登记表
```

单个非简单任务建议使用：

```text
Active/YYYY-MM-DD-任务名称/
├── TASK.md
├── work/
├── previews/
├── logs/
└── deliverables/
```

## 3. 任务分类与路由

| 类型 | 典型任务 | 正式位置 | 过程位置 |
|---|---|---|---|
| 知识整理 | 改写、总结、资料卡、索引 | 对应知识目录 | `AI Workspaces` |
| 项目研究 | 调研、纪要、需求、方案、反馈 | 对应项目目录 | `AI Workspaces` |
| 视觉讨论 | 原型比较、Logo 草案、截图 | 用户确认后进入项目 | `AI Workspaces` |
| 软件开发 | 网站、程序、自动化、测试 | 独立 Git 仓库 | 仓库自身或其 worktree |
| 知识库维护 | 重命名、归档、链接巡检 | 知识库 | 高风险操作先审批 |

无法判断类型或正式归档位置时，候选内容进入 `Review` 并询问用户，不自行创建新的顶层目录。

## 4. 正式项目流

知识库项目统一使用：

```text
需求确定 -> 搜集信息 -> 方案 -> 反馈 -> 工作记录
```

- `项目总览.md`：维护当前目标、状态、核心问题和正式方案入口。
- `工作记录.md`：按日期追加推进、判断、反馈和下一步。
- `搜集信息/`：保存可追溯事实、来源、资料卡和缺失信息。
- `方案/`：保存当前有效方案及确有必要的历史版本。
- `反馈/`：保存真实使用反馈和调整记录。

不要按每次智能体任务新增一套 `spec`、`plan`、`progress` 文档。

## 5. Superpowers 适配

| Superpowers 默认产物 | 本知识库对应 | 规则 |
|---|---|---|
| `spec` | 需求确定 | 优先更新项目总览 |
| `plan` | 方案或实施清单 | 只保留当前有效版本 |
| `progress` | 工作记录 | 按日期追加到同一文件 |
| research | 搜集信息 | 保留来源与判断边界 |
| final output | 正式成果 | 用户确认后写回 |
| feedback | 反馈 | 记录来源、结论和调整 |
| brainstorm preview | 视觉候选 | 只放外部工作区 |
| worktree | 隔离开发空间 | 仅限独立代码仓库 |

不修改全局 Superpowers 插件；通过根 `AGENTS.md`、`whiliam-vault-workflow` 和本规范覆盖它的默认保存逻辑。

## 6. 文件与命名

- 永久文档和业务文件夹使用中文业务名称。
- Delta Space、Delta X、Nomad Cube、AI、MVP、SOP 等品牌名和必要缩写保留原文。
- `AGENTS.md`、`.gitignore`、`src`、`tests`、`assets` 等工具或代码约定保留原名。
- 文件夹决定“放在哪里”，Wiki-link 决定“与什么有关”，标签用于状态或类型。
- 重命名后必须检查 Wiki-link、Markdown 链接、模板和脚本引用。

## 7. 高风险操作

以下操作必须先展示目标清单并获得明确批准：

- 批量移动、删除或重命名；
- 覆盖用户已有判断；
- 合并或删除分支；
- 创建、清理或移除 worktree；
- 将嵌套代码仓库迁出知识库；
- 连接远程仓库并推送。

不使用 `git clean`、`reset --hard` 等不可恢复清理命令处理未知内容。

## 8. Worktree 规则

- 禁止在 `D:\Whiliam local brain` 根仓库创建新的 worktree。
- 软件开发先识别真实独立 Git 仓库边界。
- 只有用户明确批准后才创建 worktree。
- 创建后立即在 `D:\AI Workspaces\WORKTREES.md` 登记任务、仓库、分支、路径、日期、状态和收尾方式。
- 任务结束时决定合并、保留还是移除；未决定的 worktree 必须保留登记，不得静默遗留。

## 9. 过程材料生命周期

- `Active`：任务执行期间保留。
- `Review`：等待用户确认，不自动删除。
- `Archive`：默认保留 30 天；到期只生成清理候选清单，不自动删除。
- 日志、截图、临时网页和可再生成文件：成果确认后进入最近一次清理清单。
- 原始资料、未确认候选成果和未合并提交：没有批准不得删除。

## 10. 任务收尾

每次任务结束必须报告：

1. 写回知识库或代码仓库的文件；
2. 仍在 `Review` 的候选成果；
3. 可清理的日志、预览和缓存；
4. 未提交改动；
5. 未关闭 worktree；
6. Git 提交与远程推送情况；
7. 恢复或继续任务所需的入口。

## 11. 自动入口

- 智能体执行规则：根目录 `AGENTS.md`。
- 任务路由与收尾：`whiliam-vault-workflow`。
- 人类可读的知识库定位：[[知识库介绍]]。
- 系统说明与历史链接兼容入口：[[Agent.md]]；不包含独立执行规则，统一指向根目录 `AGENTS.md`。
