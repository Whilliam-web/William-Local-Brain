# FDE 行业调研报告

日期：2026-07-06  
基于底稿：[[FDE行业调研底稿]]  
研究对象：FDE（Forward Deployed Engineer / Forward Deployed Engineering）作为企业 AI 落地方法、组织形态与早期创业赛道。

---

## 1. 核心结论

FDE 不是一个单纯岗位，也不是传统外包换名。它更像是 **企业 AI 从“模型能力”走向“生产工作流”的最后一公里交付机制**：由具备工程、产品、行业理解和交付能力的复合型团队，深入客户现场，把真实业务流程改写为可运行、可审计、可持续迭代的 AI / Agentic Workflow，并把交付过程中沉淀的连接器、流程模板、权限治理、评估体系和行业知识，反哺为可复用产品。

本轮调研的判断是：

1. **FDE 变热的根本原因不是岗位流行，而是企业 AI 的瓶颈转移。** 模型能力和 API 供给正在快速商品化，企业真正卡住的是数据、权限、流程、责任边界、系统集成和 ROI 验证。
2. **FDE 的机会窗口来自 Agentic AI。** 过去项目制交付难规模化，因为每个客户都不同；但 Agentic Workflow 把很多知识工作拆成“感知—判断—执行—复核—记录”的通用结构，使行业模板、执行层、记忆层、审计层有机会复用。
3. **FDE 的商业价值取决于“项目到产品”的转化率。** 如果第二个客户不能复用第一个客户 50%-60% 以上的成果，FDE 会退化成 AI 咨询/外包；如果能持续缩短交付周期、提升模块复用率、形成行业包，则可能成为高价值企业 AI 产品公司。
4. **大厂入场验证需求，但也压缩通用 FDE 服务空间。** Palantir 长期用 FDSE/FDE 模式服务复杂客户；OpenAI、Google Cloud、Anthropic、AWS 等在 2025-2026 年公开扩张 FDE / deployment 类团队。AWS 于 2026-06-30 宣布投入 10 亿美元建立 FDE 组织，说明“模型 + 云 + 前置工程”正在成为企业 AI 主流打法之一。
5. **早期创业公司的最佳切口不是“泛 FDE”，而是“高沟通密度、高人工成本、高错误成本、可量化 ROI、流程相对可模板化”的垂直场景。** 例如货代/跨境电商销售、报价、客服、法务文书、金融运营、供应链协调等。

一句话判断：**FDE 是 AI 时代企业软件从“卖工具”转向“交付结果”的过渡形态；真正值得投的不是会驻场的人力服务公司，而是能把驻场经验沉淀为行业 Agent 产品和平台能力的公司。**

## 2. FDE 的定义与边界

### 2.1 定义

FDE 可定义为：

> 一种面向复杂企业客户的前置工程交付模式：工程师深度嵌入客户业务现场，与客户的业务、工程、安全、运营团队共同定义问题、连接数据、改造流程、构建并上线 AI 系统，同时把现场交付经验沉淀为可复用的平台能力。

在 AI 语境下，FDE 的工作对象不再只是传统数据看板或业务系统，而是：

- 大模型 / 多模型调用；
- Agent workflow 编排；
- 企业知识库和语义层；
- 权限、审计、日志、监控；
- 人工兜底与复核；
- 与 CRM、ERP、IM、邮件、工单、表格、数据库等系统的集成；
- 可量化的业务结果。

### 2.2 FDE 与相邻形态的区别

| 类型 | 交付对象 | 收费逻辑 | 规模化来源 | 主要风险 |
|---|---|---|---|---|
| 咨询公司 | 诊断、方案、项目管理 | 人天 / 项目费 | 方法论和顾问杠杆 | 不拥有产品和系统，落地弱 |
| 外包团队 | 按需求开发软件 | 人天 / 需求包 | 人力扩张 | 毛利低、复用弱 |
| 传统 SaaS | 标准化软件座位 | 订阅 / seat | 产品标准化 | 难适配隐性流程 |
| AI Agent 平台 | 工具、编排、模型调用 | 用量 / seat / 平台费 | 横向平台能力 | 容易停留在 demo 或工具层 |
| FDE 型 AI 公司 | 生产工作流 + 可复用行业包 | 部署费 + 订阅 + 用量 + 结果 | 项目沉淀为模板、连接器、行业语义层 | 容易滑向项目制咨询 |

关键分界线：**FDE 不是“客户说什么就做什么”，而是通过现场交付发现可复用结构。**

## 3. 为什么 2026 年 FDE 重新变热

### 3.1 企业 AI 的瓶颈从“模型可用”转向“流程可落地”

企业已经不缺模型和工具，但缺少能把 AI 放进真实生产流程的人。典型障碍包括：

- 数据分散在 IM、邮件、Excel、ERP、CRM、行业系统中；
- 权限、合规、审计、责任归因没有设计清楚；
- 业务流程依赖老员工经验，需求无法被业务方完整表述；
- POC 可以 demo，但生产环境要处理安全、稳定性、成本、异常、回滚；
- Agent 一旦出错，需要知道谁批准、谁复核、谁负责、如何追踪证据。

这意味着企业 AI 的价值链正在从“谁的模型更强”转向“谁能把模型变成业务结果”。FDE 正好卡在这一环。

### 3.2 Agentic AI 让“项目制”重新出现产品化机会

传统企业定制难规模化，因为每家客户的表单、流程和系统都不同。但 Agentic AI 使许多知识工作出现通用结构：

1. 读取上下文；
2. 识别任务目标；
3. 调用工具；
4. 基于规则和证据判断；
5. 请求人工确认；
6. 执行结果；
7. 写回业务系统和记忆层。

因此，不同行业表面流程不同，底层可复用模块却相似：

- 数据连接器；
- 文档/聊天/表格解析；
- 任务编排；
- 审批和人工复核；
- 证据链；
- 权限和租户隔离；
- 运行日志；
- ROI 仪表盘；
- 领域知识包和 prompt 包。

FDE 的核心价值，就是从第一个客户中抽象出第二、第三个客户能复用的部分。

### 3.3 大厂用组织投入验证了需求

公开资料显示：

- Palantir 长期使用 Forward Deployed Software Engineer 模式，让工程师与客户并肩处理复杂业务和数据问题。
- OpenAI 的 FDE 岗位描述强调：FDE 负责战略客户中前沿模型的复杂端到端生产部署，覆盖 discovery、技术范围界定、系统设计、构建和上线。
- Google Cloud 的 GenAI FDE 岗位强调：FDE 是嵌入式 builder，连接 frontier AI 产品与客户生产级现实，不只是高层架构咨询，而是在客户环境内写代码、debug、共同交付 agentic solutions。
- Anthropic 的相关岗位强调：在客户系统中用 Claude 构建生产应用，交付 MCP servers、sub-agents、agent skills 等可用于生产工作流的技术资产，并把可重复部署模式反馈给产品和工程团队。
- AWS 于 2026-06-30 宣布投入 10 亿美元建立 Forward Deployed Engineering 组织，嵌入客户侧共同开发和部署 agentic AI 解决方案。

大厂进入带来两个信号：

- 正向：企业确实需要“懂 AI + 懂现场 + 能交付”的角色；
- 负向：通用型 FDE 服务会越来越拥挤，创业公司必须靠垂直行业 know-how、产品沉淀和交付效率防守。

## 4. 市场结构：FDE 不是单一行业，而是企业 AI 落地价值链

### 4.1 FDE 价值链

可将 FDE 拆为七层：

1. **行业切入**：选择有预算、有痛点、有数据、有 owner 的场景；
2. **现场诊断**：拆岗位、流程、系统、数据入口、审批节点、异常处理、责任边界；
3. **工作流建模**：把人工流程改写为 Agent 可执行任务链；
4. **数据与语义层**：接入企业系统、文件、聊天记录、历史决策，建立权限和语义结构；
5. **Agent / 系统交付**：实现工具调用、界面、日志、审计、人机协同和兜底；
6. **运行与优化**：持续观察错误、人工介入点、成本、转化率和 ROI；
7. **产品化抽象**：沉淀模板、连接器、行业知识包、评估体系、行业 SaaS 或平台能力。

第 7 层决定公司性质。没有第 7 层，FDE 只是项目交付；有第 7 层，才可能成为高倍数 VC 可投企业 AI 公司。

### 4.2 典型客户画像

适合 FDE 的客户通常有以下特征：

- 流程复杂，但不是完全非标；
- 人工成本、响应时间、错误率或合规成本可量化；
- 数据分散，但可授权接入；
- 业务部门有明确 owner，而不是 IT 创新试验；
- 改造结果能影响收入、成本、风险或交付周期；
- 客户愿意让供应商进入真实流程，而不仅是看 demo。

不适合 FDE 的场景：

- 客户只是“想接个大模型试试”；
- 没有生产系统接入；
- 没有明确 KPI 和验收标准；
- 每个客户需求完全不同；
- 团队只能做 PPT / demo，不能承担生产系统稳定性和责任。

## 5. 商业模式与单位经济

### 5.1 三种阶段

#### 阶段一：高客单项目制交付

- 收费：诊断费、部署费、实施费、培训费、私有化费；
- 价值：验证真实需求，获得客户现场数据；
- 风险：人力绑定重，交付毛利低，创始人时间不可复制。

#### 阶段二：项目制 + 可复用模块

- 收费：部署费 + 轻订阅 + 模块化扩展；
- 价值：沉淀行业知识包、连接器、workflow template、权限审计组件、ROI 看板；
- 关键指标：第二个客户复用率、交付周期下降、毛利改善。

这是早期 FDE 型 AI 创业公司最现实的阶段。

#### 阶段三：行业 SaaS / Agent 平台

- 收费：seat、任务量、流程量、API 调用量、私有化年费、结果分成；
- 价值：行业模板可复制，客户成功和销售流程标准化；
- 风险：从项目组织转产品组织，需要重建产品定义、销售、交付、CS 和合规体系。

### 5.2 关键单位经济指标

判断一家 FDE 公司是否能规模化，重点看：

| 指标 | 好信号 | 坏信号 |
|---|---|---|
| 交付周期 | 从 8 周降到 4 周，再降到 2 周 | 每个客户都重新调研和开发 |
| 复用率 | 第二个客户复用 50%-60% 以上模块 | 每次都从零做 |
| 毛利 | 随客户数量提升而改善 | 新增客户必须等比例新增工程师 |
| 收入结构 | 部署费后有订阅/用量/续费 | 只有一次性项目费 |
| 验收指标 | 报价速度、转化率、人效、错误率、响应时间等可量化 | 只说“客户体验更好” |
| 产品沉淀 | 有行业包、连接器、模板、评估集 | 只有定制代码仓库 |

## 6. 竞争格局

### 6.1 海外代表

| 类型 | 代表 | FDE 相关意义 |
|---|---|---|
| FDE 原型公司 | Palantir | 将工程师嵌入客户现场，用平台 + FDSE 解决复杂数据和运营问题 |
| 模型公司 | OpenAI、Anthropic、Cohere | 需要 FDE 把模型部署到战略客户生产工作流中 |
| 云厂商 | AWS、Google Cloud、Microsoft Azure | 将模型、云基础设施、数据治理和前置工程绑定，争夺企业 AI 落地入口 |
| Agent / 工作流平台 | LangChain、Dust、CrewAI、Zapier 等 | 提供开发与编排工具，但仍需行业落地和企业集成能力 |
| AI memory / 知识图谱 | Mem0、Zep/Graphiti、Letta 等 | 提供长期记忆、状态、语义层能力，可成为 FDE 方案底座 |

### 6.2 国内可能形态

国内 FDE 机会可能不会直接表现为“FDE 公司”，而会隐藏在以下形态中：

1. **行业 AI 员工公司**：从销售、客服、财务、法务、运营等岗位切入；
2. **AI 工作流平台**：接入飞书、企微、钉钉、邮件、表格和企业系统；
3. **垂直行业数字化服务商升级**：传统软件/实施公司加入大模型和 Agent 能力；
4. **模型/云厂商生态伙伴**：基于大厂模型和云资源做行业落地；
5. **AI infra + FDE 混合公司**：用底层记忆、RAG、workflow engine 做差异化，再通过 FDE 找 PMF。

国内创业公司最大的机会不是和大厂正面比模型，而是在垂直行业中形成：

- 更懂业务流程；
- 更快交付；
- 更愿意进入现场；
- 更灵活定价；
- 更强本地化系统集成。

## 7. 投资判断框架

### 7.1 先判断是否是真 FDE 场景

真 FDE 场景应同时具备：

- 高人工参与；
- 高沟通密度；
- 多系统切换；
- 结果可验收；
- 数据可接入；
- 流程可部分标准化；
- 客户有付费 owner。

如果只是“把模型接入企业知识库问答”，通常不构成强 FDE 机会。

### 7.2 再判断团队是否有 FDE 能力

FDE 团队需要四类能力：

1. **工程能力**：能接生产系统，处理权限、日志、稳定性和安全；
2. **Agent 能力**：会任务编排、工具调用、评估、记忆、兜底；
3. **行业理解**：能听懂客户现场语言，抽象业务流程；
4. **商业交付**：能控范围、收钱、项目管理、推动验收和续费。

纯算法团队通常缺后两项；纯咨询团队通常缺前两项。

### 7.3 最后判断产品化路径

核心问题：

- 第一个客户沉淀了哪些模块？
- 第二个客户哪些不用重做？
- 交付周期是否下降？
- 是否形成标准报价、标准部署包、标准 ROI 报告？
- 是否能从“客户说什么做什么”变成“我们知道这个行业应该怎么做”？

### 7.4 VC / FA 可用评级

| 评级 | 特征 | 建议 |
|---|---|---|
| GO | 已有付费客户，复用率明显，续费/扩展可见，团队完整 | 可积极推进融资/独家 FA |
| 积极 WAIT | 有首单或强 pipeline，路径清晰，但复用率和 ROI 待验证 | 深度约谈，要求补证据 |
| WAIT | 有技术和 demo，但客户、收入、交付不清 | 持续观察，暂不重推 |
| PASS | 本质外包或咨询，无法产品化 | 不建议投入资源 |

## 8. 对 LATRACE / 隐迹智能的项目启示

底稿中的 LATRACE 不是单纯 memory infra 项目，而是在转向：

> Cosein AI 工作平台作为执行层，LATRACE Memory Infra 作为长期状态/证据/记忆层，通过 FDE 方式切入货代、跨境电商、律所等高沟通密度行业。

这个转向是合理的。原因是：

1. 单纯 memory infra 容易被大模型厂商、Agent 平台、开源项目商品化；
2. FDE 能让团队更快接触真实业务、真实数据、真实付费；
3. 长期记忆能力如果和销售、报价、客户跟进、合同、客服等流程绑定，才更容易体现业务价值；
4. 货代/跨境电商销售场景有较强流程重复性，适合验证行业包。

但项目不能仅靠“FDE 叙事”升级估值，必须验证七件事：

1. 首个 37,200 元企业合同是否真实签署、回款和验收；
2. 3 个 AI 员工席位 + 1 个企业级 AI 中枢到底交付了哪些生产动作；
3. 客户每天有多少真实业务动作通过系统完成；
4. 报价速度、跟进率、转化率、人效、响应时间等指标是否改善；
5. 第二个货代/跨境电商客户可复用哪些模块，复用率多少；
6. LATRACE 记忆层在该场景中是否不可替代，还是普通 CRM + Agent workflow 就能完成主要价值；
7. 团队是否真正具备 GTM、项目管理、客户成功和持续交付能力。

当前建议：**积极 WAIT / 进入重点约谈**。它比纯技术概念项目更值得看，但还没到可以直接 GO 的程度。下一步约谈不应再听 BP，而应围绕“首单真实性、生产使用、ROI、复用率、毛利和续费”逐项核验。

## 9. 下一步尽调问题清单

### 9.1 客户与收入

1. 首个企业客户合同是否签署？金额、付款节点、验收标准分别是什么？
2. 已回款多少？是否有发票、合同、银行流水或客户确认？
3. 客户购买的是 PoC、部署、订阅、培训，还是完整业务结果？
4. Pipeline 中客户处于线索、试用、报价、合同还是回款阶段？
5. 客户预算来自业务部门、IT、老板个人还是创新预算？

### 9.2 交付与 ROI

1. 当前系统每天处理多少真实任务？
2. 改造前后报价速度、跟进率、转化率、人效、错误率、响应时间分别如何变化？
3. 项目投入多少人天？创始人本人投入多少？
4. 当前项目毛利如何？如果复制 10 个客户，是否需要等比例招 FDE？
5. 客户是否愿意续费、扩席或推荐同行？

### 9.3 产品化与复用

1. 第一个项目沉淀了哪些标准模块：连接器、prompt、流程模板、报价规则、客户画像、行业知识库、记忆图谱？
2. 第二个客户预计哪些不用重做？复用率多少？
3. 部署周期能否从首单缩短到 2-4 周？
4. 是否形成货代行业包 v1？包含哪些功能和验收标准？
5. 是否有标准报价体系和标准 ROI 报告模板？

### 9.4 技术壁垒

## 11. 可直接放进 FA 判断页的一句话

FDE 的投资价值不在“派工程师驻场”，而在“用驻场获得真实工作流，再把工作流沉淀为可复用行业 Agent 产品”。判断 LATRACE 这类项目的核心，不是它是否会讲 FDE，而是首个货代/跨境电商客户能否证明：真实付费、真实生产使用、真实 ROI、真实复用率，以及长期记忆层在该流程中是否构成不可替代壁垒。
