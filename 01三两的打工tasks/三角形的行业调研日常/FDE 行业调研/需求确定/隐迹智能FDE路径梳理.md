## 1. 先看隐迹智能现在到底在走什么路径

隐迹智能 / LATRACE 当前的路径，不能再简单理解为“AI 长期记忆基础设施公司”。从现有材料看，它正在从纯技术基础设施叙事，转向一个更贴近商业化的路径：

> 以 FDE 方式进入高沟通密度、流程分散、人工经验依赖强的传统行业，用 Cosein AI 工作平台承接前台执行，用 LATRACE Memory Infra 承接长期记忆、状态追踪和证据链沉淀，先做客户现场交付，再沉淀行业工作流模板和行业 AI 员工平台。

换句话说，隐迹现在不是单纯卖 memory API，也不是简单做项目外包，而是在尝试一条：

> **FDE 切入真实场景 → 验证高频工作流 → 沉淀行业包 → 转向可复制的垂直 Agent 产品**

的路线。

这一路径可以拆成三层：

### 1.1 前台：Cosein AI 工作平台

它承担的是业务执行入口，主要价值包括：

- 接入飞书、Lark、微信、邮箱、Telegram、API 等工作入口；
- 配置 AI 员工；
- 编排业务工作流；
- 执行销售、报价、客户跟进、信息整理等任务；
- 让 AI 不只是聊天，而是进入企业真实工作流。

这部分更像“企业 AI 员工 / AI 工作流平台”。

### 1.2 底层：LATRACE Memory Infra

它承担的是长期状态和记忆层，主要价值包括：

- 沉淀客户历史沟通；
- 记录业务事件和决策依据；
- 建立证据链；
- 追踪客户状态、交易阶段、历史报价、跟进动作；
- 让 Agent 能基于长期上下文持续工作。

这部分不是普通知识库问答，而是更接近“业务状态记忆层”。

### 1.3 方法：FDE 前置交付

隐迹当前的商业化路径，不是先做一个完全标准化 SaaS 再销售，而是先进入客户现场：

1. 找到高频流程；
2. 拆解岗位和任务；
3. 接入客户已有工作入口；
4. 改造一条具体工作流；
5. 收部署费和订阅费；
6. 从首单中抽象出行业包。

这就是典型 FDE 路径。

## 2. FDE 模式可能解决的行业问题

FDE 在这里真正解决的，不是“企业不会用 AI”这么宽泛的问题，而是传统行业 AI 落地中的几个结构性矛盾。

### 2.1 问题一：企业工作流高度碎片化，标准 SaaS 很难直接覆盖

很多传统行业不是没有系统，而是系统太多、入口太散：

- 客户沟通在微信 / 飞书 / 邮件；
- 报价在 Excel；
- 客户资料在 CRM 或个人表格；
- 订单状态在 ERP；
- 老板和销售的判断在聊天记录和脑子里；
- 历史经验没有结构化沉淀。

标准 SaaS 往往要求客户迁移流程，但客户不愿意换系统、不愿意培训、不愿意改变习惯。

FDE 可以解决的问题是：

> 不要求客户先重构系统，而是嵌入客户已有工作入口，在原有流程中加一层 AI 执行和记忆层。

这对中国中小 B2B 企业尤其重要，因为它们的真实业务流往往不在标准软件里，而在聊天、表格和人脑经验里。

### 2.2 问题二：业务流程依赖人工经验，难以产品化表达

在货代、跨境电商、律所、销售服务等行业，很多工作不是简单规则，而是经验判断：

- 这个客户值不值得跟；
- 报价应该参考哪些历史条件；
- 什么时间催单；
- 客户拒绝后怎么二次触达；
- 哪些信息需要人工确认；
- 哪些情况要升级给老板。

客户通常讲不清楚完整需求。传统产品经理坐在办公室里很难抽象这些流程。

FDE 的价值是通过驻场或深度共创，把隐性经验显性化：

- 拆岗位；
- 拆动作；
- 拆判断规则；
- 拆异常场景；
- 拆验收指标；
- 把人脑经验转成 Agent workflow。

### 2.3 问题三：AI demo 容易，生产落地难

很多 AI 产品可以演示：输入一个问题，生成一个答案。但企业真正需要的是：

- 接真实数据；
- 接真实账号权限；
- 接真实业务系统；
- 输出能被业务使用；
- 出错能追溯；
- 效果能衡量；
- 过程能被老板和业务负责人接受。

FDE 模式的意义是把 AI 从 demo 推到生产环境：

> 不是证明 AI “会回答”，而是证明 AI “能在业务流程里持续执行并产生结果”。

### 2.4 问题四：企业 AI 缺少长期记忆和状态追踪

传统 AI 产品常见问题是“用完即忘”：

- 上次客户说了什么；
- 上次报价是多少；
- 客户为什么犹豫；
- 这单推进到哪一步；
- 谁答应过什么；
- 下一步该谁跟进；
- 历史证据在哪里。

这些状态如果不能沉淀，AI 就只能做一次性问答，不能变成真正的 AI 员工。

隐迹的 LATRACE Memory Infra 理论上可以解决这个问题：

> 让 AI 持续记住业务对象、沟通上下文、决策依据和任务状态，从而支持跨周期的销售、报价、客服、合同、运营等工作流。

这是隐迹区别于普通 workflow 平台的潜在关键。

### 2.5 问题五：客户不知道 AI 应该怎么验收

很多企业采购 AI 时，需求是模糊的：

- “帮我提高效率”；
- “帮我做销售自动化”；
- “帮我接入大模型”；
- “帮我做 AI 员工”。

但如果没有具体指标，就无法成交、验收和续费。

FDE 可以帮助客户把模糊需求转成可验收指标，例如：

- 报价时间从 30 分钟降到 5 分钟；
- 销售每天跟进客户数提升 2 倍；
- 客户响应时间缩短 70%；
- 错单率下降；
- 客户线索覆盖率提升；
- 人工整理资料时间减少；
- 老板查看销售状态的时间减少。

这对 FA 判断也很重要：有指标，项目才有融资叙事；没指标，就只是技术试点。

## 3. FDE 模式适合解决哪些行业问题

不是所有行业都适合隐迹做 FDE。适合的行业通常具备五个特征：

1. **高沟通密度**：大量业务发生在聊天、邮件、电话、表格中；
2. **高人工经验依赖**：老员工、老板、销售的判断很关键；
3. **高频重复流程**：每天都有类似任务，不是一次性项目；
4. **ROI 可量化**：能衡量省人、提效、增收、降错；
5. **流程可部分标准化**：不同客户有差异，但底层流程相似。

基于这个标准，隐迹更适合以下方向。

### 3.1 第一优先级：货代 / 国际物流销售工作流

这是目前最适合隐迹验证的方向。

原因：

- 货代行业高度依赖销售跟进、报价、客户沟通；
- 信息分散在聊天、邮件、表格和业务系统；
- 报价、询盘、客户画像、跟进提醒等流程高频重复；
- ROI 可以量化，如报价速度、跟进率、转化率、人效；
- 行业足够垂直，有机会沉淀货代销售行业包；
- 客单价虽然不一定很高，但适合作为首个可复制模板。

隐迹不应泛泛说“我们做企业 AI 工作平台”，而应先把自己打成：

> 货代 / 国际物流销售团队的 AI 员工平台。

初期产品可以围绕：

- 客户线索整理；
- 自动调研企业信息；
- 物流需求匹配；
- 历史报价参考；
- 报价生成；
- 跟进提醒；
- 客户画像；
- 邮件 / 飞书 / 微信触达；
- 销售状态记忆。

### 3.2 第二优先级：跨境电商运营与客服工作流

跨境电商也适合，但比货代更复杂。

适合点：

- 多平台、多店铺、多语言、多渠道；
- 客服、售后、商品信息、物流状态高度碎片化；
- 大量重复沟通和运营动作；
- AI 可以帮助做客服、Listing 优化、售后处理、客户跟进、数据汇总。

风险点：

- 跨境电商工具市场较拥挤；
- 客户需求差异大；
- 平台 API、店铺权限、数据合规更复杂；
- 容易滑向工具堆叠，而不是形成核心工作流。

建议作为第二阶段，不宜一开始铺太散。

### 3.3 第三优先级：律所 / 法律服务工作流

律所场景和长期记忆、证据链、文档处理高度相关，理论上适合 LATRACE。

适合点：

- 文档多；
- 证据链重要；
- 历史案件和客户沟通需要长期记忆；
- 合同、尽调、案件管理等流程可被 AI 辅助。

风险点：

- 合规和责任要求高；
- 客户对准确性要求极高；
- 销售周期可能较长；
- 律所付费意愿和内部流程差异较大。

建议作为中期拓展方向，不建议作为当前第一主线。

### 3.4 不建议当前优先做的方向

#### 泛企业 AI 中台

太宽，容易和大厂、飞书/钉钉/企微生态、Agent 平台正面竞争。

#### 纯 Memory Infra

技术叙事好听，但商业化路径弱，容易被 OpenAI、Anthropic、字节、开源项目或 Agent 平台 commoditize。

#### 泛 FDE 服务

如果只说“我们能帮各行业做 AI 落地”，投资人会自然把它理解成咨询或外包。

#### 多行业同时推进

货代、跨境电商、律所、K12 同时讲，会显得团队没有聚焦，且每个行业都难以沉淀足够深的行业包。

## 4. 对这个团队来说，最适合的方向是什么

### 4.1 最适合的主线定位

对隐迹来说，当前最适合的方向不是“AI Memory Infra”，也不是“通用 FDE 公司”，而是：

> **从货代 / 跨境 B2B 销售工作流切入的行业 AI 员工平台，用 FDE 方式完成首批标杆客户交付，并以 LATRACE Memory Infra 作为长期状态和客户记忆壁垒。**

更短的表达可以是：

> **面向货代和跨境 B2B 企业的 AI 销售员工平台。**

或者偏融资叙事一点：

> **FDE 驱动的垂直行业 Agent 平台，首个切口是国际物流 / 跨境贸易销售工作流。**

这个定位比“长期记忆基础设施”更容易卖给客户，也比“通用企业 AI 平台”更容易被投资人理解。

### 4.2 为什么这个方向最适合他们

#### 第一，和团队已有技术资产匹配

LATRACE 的长期记忆、状态追踪、证据链能力，在销售跟进和客户状态管理里有自然价值。

例如：

- 记住客户历史询盘；
- 记住历史报价和沟通偏好；
- 记住客户卡点；
- 记住下一步跟进动作；
- 记住销售策略是否有效；
- 形成客户长期画像。

这比抽象讲“AI Agent 长期记忆”更容易落地。

#### 第二，和当前商业化信号匹配

底稿显示，项目已有国际物流销售工作流 demo 和首个企业合同信息。无论该合同后续是否完全验证，它至少说明团队已经在这个方向上开始商业化探索。

FA 判断上，应该顺着已有验证走，而不是重新发散到更多行业。

#### 第三，货代 / 跨境 B2B 销售有可量化 ROI

这个场景能问出非常具体的指标：

- 报价速度提升多少；
- 每个销售每天多跟进多少客户；
- 客户响应时间缩短多少；
- 线索覆盖率提升多少；
- 成单率是否提升；
- 销售主管是否更容易看到客户状态。

这些指标适合转化为融资材料。

#### 第四，容易从项目交付沉淀行业包

货代销售流程虽然每家公司不同，但底层模块可能相似：

- 线索录入；
- 客户画像；
- 航线 / 物流需求识别；
- 报价生成；
- 邮件生成；
- 跟进提醒；
- 客户状态追踪；
- 销售周报；
- 老板看板。

这比做“所有行业 AI 工作流”更容易形成标准模板。

### 4.3 推荐的阶段路径

#### 阶段一：只打穿货代 / 国际物流销售

目标不是签很多散客户，而是做出一个能讲清楚的标杆 case。

阶段目标：

- 1-3 个真实付费客户；
- 每个客户都有明确使用数据；
- 能证明报价、跟进、人效等指标改善；
- 沉淀货代销售 workflow template v1；
- 明确 LATRACE 记忆层在其中的不可替代价值。

#### 阶段二：从货代扩到跨境 B2B 销售

不要直接跳到所有行业，而是沿着相似工作流扩展。

可扩方向：

- 跨境电商 B2B 客户开发；
- 外贸销售；
- 国际贸易服务商；
- 供应链服务销售。

这些场景和货代共享销售、报价、客户跟进、邮件触达、客户状态记忆等能力。

#### 阶段三：形成垂直行业 Agent 平台

当货代 / 跨境 B2B 销售行业包成熟后，再讲更大的平台故事：

- 多行业 AI 员工；
- 行业 workflow marketplace；
- 企业长期记忆底座；
- AI 工作流操作系统。

但这是后话。现在不应该一上来就讲太大，不然投资人会觉得虚。

## 5. 隐迹应该避免的战略误区

### 5.1 不要把 FDE 当成主产品

FDE 是方法，不是产品。

他们不应该说“我们是一家 FDE 公司”，而应该说：

> 我们通过 FDE 方式打磨垂直行业 AI 员工产品。

### 5.2 不要同时讲太多行业

货代、跨境电商、律所、K12 如果并列讲，会削弱聚焦感。

更好的讲法是：

- 当前主线：货代 / 国际物流销售；
- 相邻扩展：跨境 B2B 销售；
- 远期可扩：律所、客服、其他高沟通密度行业。

### 5.3 不要把长期记忆讲成抽象技术

投资人和客户都不会单独为“记忆”买单。

应该讲：

- 记住客户状态；
- 记住历史报价；
- 记住跟进节奏；
- 记住决策证据；
- 让 AI 员工能持续推进客户，而不是每次重新开始。

### 5.4 不要忽视交付毛利

FDE 前期一定重，但必须证明越做越轻。

必须追踪：

- 首单投入多少人天；
- 第二单减少多少；
- 哪些模块复用；
- 标准部署包是否形成；
- 创始人是否还需要深度参与每个客户。

## 6. FA 侧对项目的建议口径

对内可以这样判断：

> 隐迹不是一个成熟的 SaaS 公司，也不是纯基础设施公司，而是处于“技术资产寻找商业场景”的早期转型期。它最有希望的路径，是通过 FDE 切入货代 / 跨境 B2B 销售工作流，将长期记忆能力嵌入真实客户跟进、报价和销售执行中，验证首批付费客户和 ROI，再沉淀为行业 AI 员工平台。

对投资人可以这样讲：

> 这个项目的看点不在于“FDE”概念本身，而在于它能否用 FDE 拿到真实场景数据，并把货代 / 跨境销售中的高频流程沉淀为可复用 Agent 产品。如果首单和第二单能证明复用率、ROI 和续费，它就从技术项目变成了早期行业 AI 应用公司。

当前状态建议：

> **积极 WAIT，重点验证首单真实性、生产使用、ROI、复用率和记忆层壁垒。验证通过后，可以按“垂直行业 AI 员工平台”方向推进。**

## 7. 下一步最该问团队的 10 个问题

1. 你们当前最想打穿的第一个行业到底是货代、跨境电商，还是泛 B2B 销售？
2. 首个国际物流客户现在是否真实上线？每天有多少业务动作通过系统完成？
3. 客户付费买的是部署、席位、培训，还是具体业务结果？
4. 改造前后报价速度、客户跟进率、人效、转化率分别有什么变化？
5. 这个项目中哪些模块可以复用到第二家货代客户？复用率多少？
6. 货代销售行业包 v1 包括哪些标准能力？
7. LATRACE Memory Infra 在这个流程中解决的不可替代问题是什么？
8. 如果不用 LATRACE，只用普通 CRM + RAG + Agent workflow，会差在哪里？
9. 第二个、第三个客户的交付周期和人天投入预计能下降多少？
10. 未来融资时，你们到底想被理解为 memory infra、AI 工作平台，还是货代 / 跨境 B2B AI 销售员工平台？

## 8. 一句话结论

隐迹智能最适合的方向，不是泛 FDE，也不是纯长期记忆基础设施，而是：
