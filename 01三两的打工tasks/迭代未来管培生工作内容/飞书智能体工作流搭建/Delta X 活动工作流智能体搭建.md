# Delta X 活动工作流智能体搭建设计文档

> 版本：v0.1 草案  
> 创建时间：2026-07-19  
> 设计原则：优先使用飞书原生智能体 / Aily / 飞书套件能力，不以 Hermes 或外部 Agent 作为主部署路径。  
> 当前阶段：需求设计与方案收敛，尚未进入实施。

---

## 1. 一句话目标

为企业搭建一个「飞书原生活动工作流智能体」，让它能基于飞书知识库中的活动 SOP、活动日历和指定活动群聊上下文，自动跟进活动推进进度、提醒风险、辅助活动启动，并在群内对 SOP 类问题进行可信回复。

---

## 2. 背景与判断

### 2.1 为什么选飞书原生智能体

当前企业知识和协作流主要沉淀在飞书中：

- 活动 SOP 已经在飞书知识库 / 云文档中形成体系；
- 活动推进依赖飞书日历、群聊、文档、表格等协作场景；
- 需要在飞书群里直接响应问题，而不是把信息搬到外部 Agent；
- 期望减少 Hermes、外部 Agent 网关或额外系统带来的权限、稳定性和维护成本。

因此本项目的优先路线是：

> 用飞书原生智能体作为主入口，用 Aily / 工作流 / 知识问答 / 飞书套件连接能力完成 MVP；只有当原生能力无法满足稳定读写、复杂状态管理或跨系统编排时，才考虑补一个轻量 OpenAPI 辅助服务。

### 2.2 与既有智能体迭代方向的关系

本地已有 [[01三两的打工tasks/郑尧涵的知识库搭建计划/智能体迭代方案/需求/智能体整体迭代需求.md]] 中提到：智能体应先支持低成本、半自动、可审核的工作流 MVP，再逐步进入 API 深度集成。

本项目继承这个原则，但做一个重要取舍：

- 不以 Hermes 自我迭代为主线；
- 不先做跨平台通用 Agent；
- 先把飞书里已经成熟的活动流 SOP、日历和群聊利用起来；
- 所有自动推进和自动回复先保留权限边界、置信度门槛和人工兜底。

## 3. 目标与非目标

### 3.1 P0 目标

1. **活动启动辅助**  
   当团队准备推一个活动时，智能体能根据活动名称、类型、日期、负责人等信息，检索对应活动 SOP，生成执行清单、时间线、负责人待办和风险提示。

2. **活动进度跟进**  
   智能体能定时查看近期活动日历、指定活动群聊中的近期消息和活动任务表，判断活动当前阶段、缺口、延期风险和下一步动作。

3. **群内 SOP 问答**  
   当群里有人 @ 智能体或触发指定关键词时，智能体能调用活动 SOP、FAQ 和历史活动经验，回答「这个活动应该怎么做」「下一步要交付什么」「这个节点谁负责」等问题。

4. **风险与缺口提醒**  
   对缺负责人、缺物料、DDL 临近、状态不明、SOP 不匹配、群聊中出现阻塞等情况，形成群内提醒或私信提醒。

5. **复盘沉淀**  
   活动结束后，智能体能根据群聊、任务状态和活动产出，生成复盘草稿，并把新问题沉淀为 FAQ / SOP 更新建议。

### 3.2 P1 目标

- 从多个活动 SOP 中自动识别最相似 SOP，并给出适配差异；
- 生成活动宣发文案、嘉宾对接话术、物料检查清单；
- 在多维表格中形成活动工作台；
- 对活动群每天 / 每周自动生成项目摘要；
- 对 SOP 老化、责任不清、流程缺失进行持续诊断。

### 3.3 暂不做的事情

- 不做未经授权的全企业群聊扫描；
- 不默认监听所有群消息并自动回复，避免打扰群聊；
- 不自动修改正式 SOP，只生成「更新建议」；
- 不自动对外发布宣发内容；
- 不自动替代负责人做最终决策；
- 不优先引入 Hermes、OpenClaw、n8n 或外部 Agent 编排层。

## 4. 关键用户与使用场景

| 角色 | 主要诉求 | 智能体应提供的帮助 |
|---|---|---|
| 活动总负责人 | 快速知道活动是否按节奏推进 | 每日 / 每周进度摘要、风险列表、阻塞提醒 |
| 活动执行同学 | 不清楚当前阶段该干什么 | 从 SOP 生成当前阶段任务和检查清单 |
| 宣发 / 设计同学 | 需要知道物料节点和文案需求 | 输出物料清单、文案方向、交付时间 |
| 嘉宾 / 选手对接同学 | 需要话术和对接节点 | 生成对接模板、提醒沟通节点 |
| SOP 维护者 | 想知道 SOP 哪里过时 | 活动复盘后生成 SOP 更新建议 |
| 新加入群成员 | 不知道活动背景和流程 | @ 智能体后获得背景摘要和下一步指引 |

## 5. Superpower 方案发散：三种路线

### 路线 A：纯知识问答型智能体

**做法：** 只接入飞书知识库 / SOP，配置知识问答和群聊机器人。  
**优点：** 上手快，权限简单，适合先验证 SOP 问答质量。  
**缺点：** 对活动状态、日历节点、任务推进的主动跟踪弱；难以形成完整项目推进闭环。  
**适用：** 仅想做「活动 SOP 答疑机器人」时。

### 路线 B：Aily 工作流 + 知识问答 + 多维表格 / 日历

**做法：** 用 Aily 智能体作为入口，知识问答负责 SOP 检索，工作流负责进度巡检、群聊分析、风险判断和消息回复，多维表格承接活动状态。  
**优点：** 保持飞书原生部署，又能覆盖「查 SOP + 查日历 + 看群聊 + 跟状态 + 回复」的主需求。  
**缺点：** 需要设计好数据表、权限、触发器和置信度策略。  
**适用：** 本项目推荐路线。

### 路线 C：飞书原生智能体 + 轻量 OpenAPI 辅助服务

**做法：** 前端仍是飞书原生智能体，但在原生节点无法完成复杂检索、聚合或状态判断时，由一个内部轻量服务调用飞书 OpenAPI 并返回结构化结果。  
**优点：** 能处理更复杂的状态计算、权限隔离、日志审计和定制算法。  
**缺点：** 多一套服务部署、鉴权、监控和维护成本。  
**适用：** 当路线 B 的原生工作流在稳定性、复杂逻辑或性能上不够时再引入。

### 推荐结论

先走 **路线 B**：

> Aily 原生智能体 + 知识问答 + 工作流 + 飞书消息触发 / 定时触发 + 多维表格活动工作台。

并为路线 C 预留接口边界，但不在 MVP 阶段实现。

## 6. 总体架构

```text
用户 / 活动群
  ↓ @智能体 / 关键词 / 新群消息 / 定时任务
飞书原生智能体 Aily
  ├─ 对话层：群内问答、私聊、机器人渠道
  ├─ 知识层：活动 SOP、FAQ、历史活动复盘、模板文档
  ├─ 工作流层：活动启动、进度巡检、群聊分析、风险提醒、复盘生成
  ├─ 状态层：多维表格活动工作台
  └─ 飞书套件能力：日历、消息、文档/知识库、群组、任务/提醒
```

### 6.1 对话层

负责和用户交互：

- 群内被 @ 时回复；
- 可选：指定关键词触发；
- 私聊查询活动状态；
- 自动发送定时摘要；
- 对低置信度问题转人工确认。

### 6.2 知识层

负责回答「应该怎么干」：

- 活动 SOP；
- 活动类型分类；
- 阶段检查清单；
- 宣发 / 设计 / 嘉宾 / 报名 / 现场执行模板；
- 历史活动复盘；
- 高频问题 FAQ；
- 禁止自动回答的问题边界。

### 6.3 工作流层

负责把知识变成动作：

- 根据活动日期倒推 timeline；
- 根据 SOP 判断当前阶段；
- 根据群聊提取任务、阻塞和风险；
- 根据日历识别近期活动；
- 根据任务表判断延期和缺口；
- 生成摘要、提醒、问答回复和复盘草稿。

### 6.4 状态层

建议用飞书多维表格承接活动状态，避免智能体只依赖上下文临时判断。

核心状态包括：

- 活动基本信息；
- 活动阶段；
- 负责人；
- 关键节点；
- 任务状态；
- 关联 SOP；
- 关联日历；
- 关联群聊；
- 风险等级；
- 最近一次巡检结论。

## 7. 数据模型设计

### 7.1 活动总表

| 字段 | 类型 | 说明 |
|---|---|---|
| event_id | 文本 | 活动唯一 ID |
| 活动名称 | 文本 | 如「Delta X Demo Day」 |
| 活动类型 | 单选 | 分享会 / 招募 / 路演 / 工作坊 / 内部会 / 其他 |
| 活动日期 | 日期 | 从飞书日历同步或手动填写 |
| 当前阶段 | 单选 | 筹备中 / 宣发中 / 报名中 / 执行前 / 进行中 / 复盘中 / 已结束 |
| 总负责人 | 人员 | 活动 owner |
| 执行群 | 群聊 ID / 链接 | 指定智能体可读取的群 |
| 日历事件 | 日程 ID / 链接 | 对应飞书日历事件 |
| 匹配 SOP | 关联记录 | 关联 SOP 索引表 |
| 风险等级 | 单选 | 低 / 中 / 高 / 阻塞 |
| 下一步动作 | 长文本 | 智能体生成，但需负责人确认 |
| 最近巡检时间 | 时间 | 自动更新 |
| 最近巡检摘要 | 长文本 | 自动生成摘要 |

### 7.2 SOP 索引表

| 字段 | 类型 | 说明 |
|---|---|---|
| sop_id | 文本 | SOP 唯一 ID |
| SOP 名称 | 文本 | 活动流程名称 |
| 适用活动类型 | 多选 | 该 SOP 可覆盖的活动类型 |
| SOP 文档链接 | 链接 | 飞书知识库 / 云文档链接 |
| 阶段清单 | 长文本 | 活动阶段拆分 |
| 必备交付物 | 长文本 | 每阶段必须产出什么 |
| 高频问题 | 关联记录 | 关联 FAQ 表 |
| 维护人 | 人员 | SOP owner |
| 最近更新时间 | 日期 | 判断 SOP 是否过时 |
| 版本状态 | 单选 | 正式 / 草案 / 需更新 / 已废弃 |

### 7.3 任务跟进表

| 字段 | 类型 | 说明 |
|---|---|---|
| task_id | 文本 | 任务唯一 ID |
| 关联活动 | 关联记录 | 对应活动 |
| 阶段 | 单选 | 对应 SOP 阶段 |
| 任务名称 | 文本 | 具体待办 |
| 负责人 | 人员 | owner |
| DDL | 日期 | 截止时间 |
| 状态 | 单选 | 未开始 / 进行中 / 待确认 / 已完成 / 延期 / 阻塞 |
| 来源 | 单选 | SOP 生成 / 群聊提取 / 人工新增 / 复盘新增 |
| 证据 | 长文本 | 对应群聊摘要、文档链接或用户确认 |
| 置信度 | 数字 | 智能体提取任务时使用 |
| 提醒策略 | 单选 | 不提醒 / D-3 / D-1 / 当天 / 逾期 |

### 7.4 群聊观察表

| 字段 | 类型 | 说明 |
|---|---|---|
| record_id | 文本 | 观察记录 ID |
| 关联活动 | 关联记录 | 对应活动 |
| 消息时间 | 时间 | 群聊消息时间 |
| 发送人 | 人员 / 文本 | 发言人 |
| 消息摘要 | 长文本 | 不建议保存过长原文 |
| 识别类型 | 单选 | 问题 / 决策 / 任务 / 风险 / 资料 / 闲聊 |
| 提取结论 | 长文本 | 智能体结构化结果 |
| 是否需要回复 | 勾选 | 是否需要群内响应 |
| 是否已处理 | 勾选 | 是否已生成任务、回答或提醒 |

### 7.5 FAQ / 问答沉淀表

| 字段 | 类型 | 说明 |
|---|---|---|
| question_id | 文本 | 问题 ID |
| 问题 | 长文本 | 高频问法 |
| 标准回答 | 长文本 | 可直接回复群内的答案 |
| 依据来源 | 链接 | SOP 文档、复盘文档或负责人确认 |
| 适用活动类型 | 多选 | 问题适用范围 |
| 置信等级 | 单选 | 高 / 中 / 低 |
| 是否允许自动回复 | 勾选 | 高风险问题默认不允许 |
| 维护人 | 人员 | FAQ owner |

## 8. 核心工作流设计

### 8.1 工作流一：新活动启动

**触发方式：**

- 负责人私聊智能体：「帮我启动一个 XX 活动」；
- 活动群 @ 智能体：「这个活动怎么推进？」；
- 活动总表新增一条记录；
- 飞书日历中新增带指定标签的活动。

**流程：**

1. 收集活动基础信息：名称、类型、日期、目标、负责人、活动群；
2. 检索 SOP 索引表，匹配最可能的 SOP；
3. 若匹配置信度低，列出 2-3 个候选 SOP 让负责人选择；
4. 根据 SOP 和活动日期倒推 timeline；
5. 生成任务跟进表初稿；
6. 输出启动摘要到活动群；
7. 要求负责人确认任务表后再进入自动巡检。

**群内输出模板：**

```markdown
我已按《{SOP 名称}》为本活动生成启动清单。

- 当前阶段：{阶段}
- 关键日期：{活动日期}
- 近期最重要 3 件事：
  1. {任务1}（负责人：{人}，DDL：{日期}）
  2. {任务2}（负责人：{人}，DDL：{日期}）
  3. {任务3}（负责人：{人}，DDL：{日期}）
- 需要负责人确认：{待确认项}

依据：{SOP 文档链接}
```

### 8.2 工作流二：定时进度巡检

**触发方式：**

- 每天固定时间；
- 每周固定时间；
- 活动前 D-14 / D-7 / D-3 / D-1；
- 负责人手动触发：「巡检一下这个活动」。

**输入：**

- 未来 7 / 14 / 30 天活动日历；
- 活动总表；
- 任务跟进表；
- 指定活动群近期消息；
- 关联 SOP 的阶段要求。

**处理逻辑：**

1. 找出近期活动；
2. 识别每个活动当前应处阶段；
3. 对照 SOP 检查必备任务是否存在；
4. 对照任务表检查 DDL 和状态；
5. 从群聊中提取新增问题、阻塞、决策和任务；
6. 生成风险等级；
7. 输出摘要和提醒。

**输出形式：**

- 群内简短摘要；
- 私信负责人详细风险；
- 多维表格更新巡检摘要；
- 必要时生成待确认任务。

### 8.3 工作流三：群内 SOP 问答

**触发方式：**

- 默认：用户 @ 智能体；
- 可选：指定关键词，如「SOP」「流程」「下一步」「谁负责」「怎么做」；
- 暂不建议一开始对所有群消息自动回复。

**问题分类：**

| 类型 | 示例 | 响应策略 |
|---|---|---|
| SOP 查询 | “这个活动宣发什么时候开始？” | 检索 SOP 后直接回复 |
| 进度查询 | “报名表做好了吗？” | 查任务表 + 群聊摘要，给状态和负责人 |
| 责任查询 | “这个谁负责？” | 查任务表，若缺失则提醒 owner 确认 |
| 资料查询 | “海报模板在哪？” | 查 SOP / 知识库 / 文档搜索 |
| 决策类问题 | “要不要改活动时间？” | 不直接决策，整理依据并 @负责人 |
| 低置信问题 | SOP 找不到或冲突 | 明确说明不确定，给候选来源并转人工 |

**自动回复规则：**

- 高置信 SOP / FAQ 问题：可自动回复；
- 中置信问题：回复时标注「可能依据」，并建议负责人确认；
- 低置信或决策类问题：只生成草稿或 @负责人；
- 涉及外部发布、预算、合作承诺、人员评价：不自动回复结论。

### 8.4 工作流四：活动风险提醒

**风险规则示例：**

| 风险 | 触发条件 | 处理 |
|---|---|---|
| DDL 临近 | 任务 D-1 未完成 | 群内提醒负责人 |
| 负责人缺失 | SOP 必备任务无 owner | @活动总负责人确认 |
| 物料缺失 | D-3 未找到海报 / 推文 / 报名表 | 标记高风险 |
| 群聊出现阻塞 | 多人提到“卡住”“没人负责”“来不及” | 生成阻塞摘要 |
| SOP 不匹配 | 活动类型与 SOP 低匹配 | 请求人工选择 SOP |
| 信息冲突 | 日历时间与群内时间不一致 | 提醒确认，以日历为临时准据 |

### 8.5 工作流五：活动复盘沉淀

**触发方式：**

- 活动结束后 D+1；
- 负责人手动触发；
- 活动状态变成「复盘中」。

**输出：**

- 活动复盘草稿；
- 数据与执行过程摘要；
- 群聊中的关键决策和问题；
- SOP 偏差清单；
- 新 FAQ 候选；
- 下次活动可复用模板。

**原则：**

复盘只生成建议，不直接覆盖 SOP 正文。SOP owner 审核后再更新正式文档。

## 9. 智能体人格与回复规范

### 9.1 角色定位

智能体不是「聊天机器人」，而是：

> 活动 SOP 管理员 + 活动项目助理 + 群内流程答疑员 + 风险提醒员。

### 9.2 回复风格

- 中文；
- 简短、明确、可执行；
- 先结论，后依据；
- 永远说明依据来源；
- 不确定时说不确定；
- 不替负责人做高风险决策；
- 能生成下一步动作时，直接给 checklist。

### 9.3 标准回复结构

```markdown
结论：{直接回答}

依据：{SOP / FAQ / 任务表 / 日历 / 群聊摘要来源}

下一步：
- {动作1}
- {动作2}

需要确认：{如无则省略}
```

## 10. 权限与安全设计

### 10.1 最小权限原则

MVP 阶段只授权：

- 指定活动 SOP 知识库；
- 指定活动群；
- 指定活动日历；
- 指定多维表格；
- 指定输出群 / 私信对象。

不做全企业知识库、全群聊、全日历读取。

### 10.2 群聊监听策略

推荐分三档：

| 档位 | 监听方式 | 适用阶段 |
|---|---|---|
| L1 | 仅 @ 智能体时回复 | MVP 默认 |
| L2 | 指定关键词触发 | 试点稳定后 |
| L3 | 新增群消息均分析 / 自动回复 | 只在高价值低噪音群使用，且需审批 |

原因：飞书机器人默认更适合被 @ 时回复；若开启新增群消息均自动回复，可能对群聊造成干扰，并通常需要额外权限审批。

### 10.3 数据留存策略

- 群聊原文不建议长期全量保存；
- 保存结构化摘要、任务、风险和依据链接即可；
- 对涉及个人隐私、薪酬、商业敏感合作等内容设置不处理或脱敏；
- 复盘和 SOP 更新建议必须保留来源和审核人。

### 10.4 人工审核边界

必须人工确认的事项：

- 正式 SOP 修改；
- 对外发布文案；
- 活动时间变更；
- 预算、合作权益、商务承诺；
- 人员安排变更；
- 高风险群内公开回复。

## 11. MVP 范围

### 11.1 MVP 只验证一个闭环

建议先选 1 个真实活动类型、1 个活动群、1 套 SOP、1 张多维表格，验证：

```text
活动启动
→ 匹配 SOP
→ 生成 timeline / 任务
→ 定时巡检
→ 群内问答
→ 风险提醒
→ 复盘草稿
```

### 11.2 MVP 不追求的事情

- 不覆盖所有活动类型；
- 不追求完全自动化；
- 不做复杂跨系统写入；
- 不做长期记忆自优化；
- 不做大规模历史活动迁移。

### 11.3 MVP 验收指标

| 指标 | 验收标准 |
|---|---|
| SOP 匹配准确率 | 试点活动中，负责人认为匹配正确率 ≥ 80% |
| 群内问答可用率 | SOP 类问题中，可直接回答或给出正确来源 ≥ 80% |
| 进度巡检准确率 | 每次摘要中错误状态 ≤ 1 条 |
| 风险提醒有效性 | 至少能提前发现 DDL / owner / 物料缺失类风险 |
| 人工打扰控制 | 群成员反馈不觉得机器人刷屏 |
| 复盘沉淀 | 每场活动后至少沉淀 3 条 SOP / FAQ 更新建议 |

## 13. 主要风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| SOP 文档不够结构化 | 知识问答答非所问 | 先做 SOP 索引和 FAQ 拆分 |
| 群聊噪音太高 | 智能体误判进度 | MVP 仅读取指定群 + 仅提取结构化事件 |
| 权限不足 | 不能读日历 / 群聊 / 知识库 | Phase 0 先做权限清单 |
| 自动回复打扰群聊 | 回复过多或不合时宜 | 默认只 @ 回复，关键词触发后置 |
| 状态来源冲突 | 日历、群聊、表格说法不一致 | 标记冲突，不直接裁决，@负责人确认 |
| SOP 老化 | 按旧流程提醒错误事项 | 每次复盘生成 SOP 更新建议 |
| 责任边界不清 | 机器人被当成负责人 | 所有决策类问题转人工，机器人只做整理和提醒 |

## 14. 待确认问题

1. 试点活动类型是哪一个？分享会、路演、工作坊、招募活动，还是其他？
2. 试点 SOP 在飞书知识库中的具体路径是哪一个？
3. 是否已经有活动总表 / 任务表，还是需要新建多维表格？
4. 智能体是否允许读取指定群的历史消息？允许读取多长时间范围？
5. 群内自动回复先采用「仅 @ 回复」，还是允许关键词触发？
6. 活动负责人希望收到群内提醒、私信提醒，还是每日摘要？
7. 哪些问题必须禁止智能体自动回答？例如预算、合作权益、嘉宾承诺、对外发布等。
8. 飞书企业当前是否已开通 Aily / 飞书智能伙伴创建平台相关权限？

## 15. 下一步建议

建议下一步不要直接搭完整智能体，而是先做一个 **MVP 配置包**：

1. 选定一个试点活动；
2. 把该活动 SOP 拆成「阶段 - 任务 - 交付物 - FAQ」；
3. 建一张活动工作台多维表格；
4. 创建 Aily 智能体；
5. 先开启 @ 回复和手动巡检；
6. 跑一轮活动后，再决定是否开启关键词触发和定时自动巡检。

如果这份设计方向确认，下一步可以继续输出：

- `活动工作台多维表格字段模板`；
- `Aily 工作流节点配置清单`；
- `活动 SOP 拆解模板`；
- `群内问答 Prompt / 回复规则`；
- `MVP 实施计划`。
