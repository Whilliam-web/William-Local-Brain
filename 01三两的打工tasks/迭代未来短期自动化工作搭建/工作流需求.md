# 工作流需求文档：迭代未来短期自动化工作搭建

## 0. 原始需求摘录

> 宣发，按照 timeline 提醒，直接生成，发给 yy，排版之后，接入 Figma 完成排版。  
> 宣发完成，生成对应宣发渠道的文案，小红书填入多维表格。（自动化）  
> 以上内容按阶段节点，给出提醒信息。  
> 嘉宾对接 / 选手对接：发信息 SOP，大概时间节点，给文案。按模板做替换。  
> 设置一个 Word 格式模板（纯格式）——这个我不确定 Codex。  
> 人员安排、分工，放在多维表格里，分析聊天记录，发布任务提醒，落实到日程，跟踪进度。

## 1. 需求目标

搭建一套面向「短期活动 / 项目迭代」的半自动化工作流，让活动推进过程中重复发生的事项可以被标准化、提醒化、模板化和自动生成。

核心目标：

1. **按 timeline 自动提醒**：根据活动阶段和关键节点，提前提醒相关负责人。
2. **自动生成宣发内容**：根据活动信息生成不同渠道的宣发文案，并流转到负责人审核 / 排版。
3. **对接 SOP 模板化**：嘉宾、选手、合作方等对接话术按模板替换变量，减少重复写消息。
4. **任务分工可追踪**：人员安排、任务分工、DDL、状态集中放入多维表格，并可同步提醒和日程。
5. **聊天记录辅助分析**：从群聊 / 私聊记录中提取任务、负责人、时间节点和风险点。
6. **成果进入设计流程**：宣发文案经过审核后，进入 Figma / 设计排版流程，形成可发布物料。

## 2. 使用场景

### 2.1 活动宣发流程

当一个活动进入宣发阶段后，系统根据预设 timeline 自动提醒：

- 什么时候准备首轮宣发文案；
- 什么时候交给 yy 或对应负责人审核；
- 什么时候进入排版；
- 什么时候接入 Figma 完成视觉设计；
- 什么时候按渠道发布；
- 发布后需要记录哪些渠道、发布时间和链接。

### 2.2 小红书 / 公众号 / 社群等渠道文案生成

同一个活动信息需要适配不同渠道：

- 小红书：标题、正文、话题标签、封面建议、评论区引导；
- 公众号：标题、摘要、长文结构、排版建议；
- 社群：短消息、报名链接、强调截止时间；
- 朋友圈：更口语化、更短的转发文案；
- 海报 / Figma：主标题、副标题、时间地点、嘉宾信息、行动按钮。

### 2.3 嘉宾 / 选手对接

围绕嘉宾或选手对接，沉淀固定 SOP：

- 初次邀请；
- 确认参与；
- 收集资料；
- 提醒提交材料；
- 活动前确认；
- 活动当天提醒；
- 活动后感谢和复盘收集。

每一步都需要：

- 对应时间节点；
- 可替换模板；
- 需要填写的变量；
- 默认负责人；
- 是否需要同步到日程 / 任务提醒。

### 2.4 人员安排与进度跟踪

项目负责人将人员、任务、DDL、状态放入多维表格。系统辅助完成：

- 根据聊天记录识别新增任务；
- 生成任务提醒；
- 同步到日程；
- 汇总当前进度；
- 标记逾期任务；
- 输出每日 / 每阶段推进摘要。

## 3. 角色与权限

| 角色 | 主要职责 | 需要的能力 |
| --- | --- | --- |
| 项目负责人 | 创建项目、维护 timeline、确认任务分工 | 查看全部信息、修改任务、确认发布 |
| 宣发负责人 | 生成 / 修改宣发文案、推进渠道发布 | 查看活动信息、编辑文案、更新渠道状态 |
| 设计 / 排版负责人 | 接收文案，完成 Figma / 海报 / 长图排版 | 查看已确认文案、更新设计状态 |
| 嘉宾 / 选手对接负责人 | 按 SOP 发送消息，记录反馈 | 使用话术模板、更新对接状态 |
| 执行成员 | 完成被分配任务 | 查看自己的任务和 DDL |
| AI / 自动化助手 | 生成文案、提取任务、发提醒、生成摘要 | 读取授权数据、写入表格 / 日程 / 草稿 |

## 4. 核心功能需求

### 4.1 项目基础信息表

每个活动 / 项目需要有一个基础信息入口，作为后续生成文案和任务的原始数据。

建议字段：

| 字段   | 说明                    | 示例                     |
| ---- | --------------------- | ---------------------- |
| 项目名称 | 活动 / 项目名称             | 迭代未来线下分享会              |
| 项目类型 | 活动、比赛、课程、招募等          | 活动                     |
| 活动时间 | 开始和结束时间               | 2026-07-20 19:00-21:00 |
| 活动地点 | 线上 / 线下地点             | 上海 / 腾讯会议              |
| 目标人群 | 面向谁                   | 高校学生、创业者               |
| 核心卖点 | 宣发重点                  | 嘉宾经验、实战案例              |
| 报名方式 | 链接 / 二维码 / 表单         | 飞书表单链接                 |
| 负责人  | 总负责人                  | xxx                    |
| 当前阶段 | 筹备中 / 宣发中 / 执行中 / 复盘中 | 宣发中                    |
| 备注   | 其他信息                  | 需提前收嘉宾照片               |

### 4.2 Timeline 节点提醒

需要建立一张「阶段节点表」，系统根据日期自动生成提醒。

建议节点：

| 阶段    | 相对时间        | 任务                | 默认提醒对象 | 输出物           |
| ----- | ----------- | ----------------- | ------ | ------------- |
| 项目立项  | T-14 ~ T-10 | 填写项目基础信息、确认负责人    | 项目负责人  | 项目信息表         |
| 宣发准备  | T-10 ~ T-7  | 生成首版宣发文案          | 宣发负责人  | 多渠道文案草稿       |
| 设计排版  | T-7 ~ T-5   | 将确认文案交给设计 / Figma | 设计负责人  | 海报 / 长图 / 模板稿 |
| 首轮发布  | T-5 ~ T-3   | 小红书、社群、朋友圈等发布     | 宣发负责人  | 渠道发布记录        |
| 对接确认  | T-5 ~ T-2   | 嘉宾 / 选手信息确认       | 对接负责人  | 确认记录          |
| 活动前提醒 | T-1         | 向参与者 / 嘉宾发送提醒     | 对接负责人  | 提醒消息          |
| 活动当天  | T           | 检查物料、人员、流程        | 项目负责人  | 执行 checklist  |
| 活动后   | T+1 ~ T+3   | 感谢、复盘、数据整理        | 项目负责人  | 复盘文档          |

功能要求：

- 支持基于活动日期自动倒推节点；
- 支持手动调整某个节点日期；
- 支持给不同负责人发送不同提醒；
- 支持提醒状态：未提醒、已提醒、已完成、已逾期；
- 支持将重要节点同步到日历。

### 4.3 宣发文案生成

输入项目基础信息后，自动生成不同渠道文案。

#### 4.3.1 输入

- 项目基础信息；
- 渠道类型；
- 目标人群；
- 语气风格；
- 字数范围；
- 是否需要标题 / 标签 / CTA；
- 是否已有参考文案。

#### 4.3.2 输出

| 渠道 | 输出内容 |
| --- | --- |
| 小红书 | 3-5 个标题、正文、话题标签、封面文字建议、评论区引导 |
| 社群 | 3 个不同长度的群发版本：短版、标准版、催报名版 |
| 朋友圈 | 个人转发版、官方口吻版 |
| 公众号 | 标题、摘要、正文大纲、开头和结尾 |
| Figma / 海报 | 主标题、副标题、关键信息、按钮文案、视觉层级建议 |

#### 4.3.3 流转

1. AI 生成初稿；
2. 宣发负责人审核；
3. 修改后标记为「已确认」；
4. 自动进入设计 / 排版任务；
5. 发布后将链接 / 截图 / 发布时间填入渠道记录表。

### 4.4 Figma / 设计排版衔接

目标不是让 AI 完全替代设计，而是把「已确认文案」整理成设计可直接使用的结构。

需要输出：

- 海报主标题；
- 副标题；
- 时间地点；
- 嘉宾 / 选手信息；
- 报名方式；
- CTA 按钮；
- 封面文字；
- 设计备注。

可选开发方式：

1. **轻量版**：生成一份「Figma 排版文案表」，人工复制到 Figma；
2. **进阶版**：用 Figma API / 插件将文案写入指定图层；
3. **模板版**：固定 Figma 模板图层命名，自动替换文本内容。

第一阶段建议先做轻量版，确保文案结构稳定，再考虑 API 接入。

### 4.5 小红书多维表格自动填入

小红书渠道建议单独建表，字段如下：

| 字段 | 说明 |
| --- | --- |
| 项目名称 | 关联项目 |
| 标题 1 | 备选标题 |
| 标题 2 | 备选标题 |
| 标题 3 | 备选标题 |
| 正文 | 小红书正文 |
| 话题标签 | #标签 |
| 封面文案 | 用于封面的短句 |
| 发布时间 | 计划 / 实际发布时间 |
| 发布人 | 负责账号或人员 |
| 状态 | 草稿、待审核、待发布、已发布 |
| 发布链接 | 发布后填写 |
| 数据反馈 | 浏览、点赞、收藏、评论等 |

自动化要求：

- 根据项目基础信息生成小红书字段；
- 自动写入多维表格；
- 支持人工修改；
- 状态变更后触发下一步提醒。

### 4.6 嘉宾 / 选手对接 SOP

建立「对接对象表」和「消息模板库」。

#### 对接对象表字段

| 字段 | 说明 |
| --- | --- |
| 姓名 | 嘉宾 / 选手姓名 |
| 类型 | 嘉宾、选手、合作方、志愿者 |
| 联系方式 | 微信 / 电话 / 邮箱 |
| 当前状态 | 待邀请、已邀请、已确认、待补资料、已完成 |
| 负责人 | 对接人 |
| 下一步动作 | 要发送什么消息 |
| 下次提醒时间 | 自动提醒时间 |
| 备注 | 特殊信息 |

#### 消息模板字段

| 字段 | 说明 |
| --- | --- |
| 模板名称 | 如：初次邀请、资料收集、活动前提醒 |
| 适用对象 | 嘉宾 / 选手 / 合作方 |
| 使用阶段 | T-10、T-5、T-1 等 |
| 模板正文 | 带变量的消息内容 |
| 变量 | 姓名、活动名、时间、地点、链接等 |

示例模板：

```text
{姓名} 你好～我们是 {项目名称} 的项目组，想邀请你参与本次活动。
活动时间是 {活动时间}，主题是 {活动主题}。
如果你方便的话，我们想进一步和你确认参与形式与所需资料。
```

功能要求：

- 根据对象类型推荐对应模板；
- 自动替换变量；
- 生成可复制消息；
- 记录是否已发送；
- 到时间自动提醒负责人继续跟进。

### 4.7 Word 格式模板

这里的需求可以拆成两层：

1. **纯格式模板**：用于活动策划案、对外邀请函、复盘文档等；
2. **内容填充模板**：在固定格式中自动填入项目名称、时间、地点、介绍等变量。

建议先做：

- 一个 `.docx` 样式模板；
- 一份变量说明表；
- 一份 Markdown 版本模板，方便 AI 生成内容；
- 后续再用脚本或 Word 模板机制批量生成 `.docx`。

需要确认：

- Word 模板主要用于哪类文档；
- 是否必须生成 `.docx`，还是 Markdown / 飞书文档也可以；
- 是否有现成品牌格式或视觉规范。

### 4.8 聊天记录分析与任务提取

输入聊天记录后，AI 辅助识别：

- 谁承诺了什么任务；
- 任务截止时间；
- 当前阻塞点；
- 需要提醒的人；
- 可以同步到任务表 / 日程的事项。

输出格式：

| 任务 | 负责人 | 截止时间 | 来源聊天摘要 | 建议动作 | 置信度 |
| --- | --- | --- | --- | --- | --- |

安全要求：

- 不自动发送消息，先生成待确认列表；
- 由项目负责人确认后再写入任务表；
- 保留来源摘要，方便追溯；
- 对不确定任务标记「需人工确认」。

### 4.9 任务提醒、日程与进度追踪

任务表字段建议：

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 要做什么 |
| 所属项目 | 关联项目 |
| 负责人 | 谁负责 |
| 协作人 | 其他参与者 |
| 截止时间 | DDL |
| 提醒时间 | 什么时候提醒 |
| 状态 | 未开始、进行中、待审核、已完成、已逾期 |
| 优先级 | 高 / 中 / 低 |
| 来源 | 手动创建、聊天记录、timeline 自动生成 |
| 备注 | 补充说明 |

功能要求：

- 新任务可自动生成提醒；
- 重要任务同步到日程；
- 每天 / 每阶段输出进度摘要；
- 逾期任务自动标红或提醒；
- 支持按项目、负责人、状态筛选。

## 6. 自动化流程设计

### 6.1 新建项目流程

```text
填写项目基础信息
→ 自动生成 timeline
→ 自动生成默认任务
→ 分配负责人
→ 创建提醒
→ 生成首批宣发 / 对接草稿
```

### 6.2 宣发流程

```text
项目进入宣发阶段
→ AI 生成多渠道文案
→ 写入宣发文案表
→ 通知宣发负责人审核
→ 审核通过后生成 Figma 排版文案
→ 通知设计负责人排版
→ 发布后更新渠道记录
→ 到期自动提醒数据回收
```

### 6.3 嘉宾 / 选手对接流程

```text
添加对接对象
→ 根据对象类型和阶段匹配 SOP 模板
→ 自动替换变量生成消息
→ 负责人复制 / 发送
→ 更新对接状态
→ 自动设置下一次提醒
```

### 6.4 聊天记录到任务流程

```text
导入 / 粘贴聊天记录
→ AI 提取候选任务
→ 人工确认任务
→ 写入任务分工表
→ 创建提醒 / 日程
→ 持续跟踪状态
```

## 7. 开发方案

### 7.1 第一阶段：可用的低成本版本

目标：先把流程跑通，不追求全自动。

建议实现：

- 用多维表格搭建数据表；
- 用固定字段沉淀项目基础信息；
- 用 AI 生成宣发文案、对接话术、任务提取结果；
- 用人工复制方式进入微信 / 小红书 / Figma；
- 用表格状态字段触发提醒；
- Word 模板先用 Markdown + `.docx` 样式模板并行。

优点：

- 开发成本低；
- 容易调试；
- 不依赖复杂 API；
- 适合快速验证真实需求。

### 7.2 第二阶段：半自动化版本

目标：减少复制粘贴和人工整理。

建议实现：

- 多维表格字段标准化；
- 脚本 / 自动化工具将 AI 结果写入多维表格；
- 表格状态变化后自动发送提醒；
- 日程自动创建；
- Figma 输出结构化排版文案；
- 聊天记录分析后自动生成「待确认任务」。

### 7.3 第三阶段：深度集成版本

目标：让系统成为项目推进中台。

可能实现：

- Figma API 自动替换模板图层；
- 飞书 / 微信 / 邮件消息草稿自动生成；
- 多维表格、日历、任务、文档互相同步；
- 每日自动生成项目进度摘要；
- 自动识别风险和逾期事项；
- 形成项目复盘和知识沉淀。

## 8. 需要准备的东西

### 8.1 业务侧需要准备

- 常见项目类型清单；
- 每类项目的标准 timeline；
- 常见宣发渠道；
- 过往优质宣发文案；
- 嘉宾 / 选手对接话术；
- 常见任务分工方式；
- 项目负责人、宣发负责人、设计负责人等角色列表；
- 是否有固定品牌语气和视觉规范。

### 8.2 工具侧需要准备

- 多维表格工具：飞书多维表格 / Airtable / Notion Database 等；
- 日历工具：飞书日历 / Google Calendar / Outlook；
- 设计工具：Figma；
- 文档工具：Word / 飞书文档 / Markdown；
- AI 生成工具：Codex / ChatGPT / 其他 LLM；
- 自动化工具：飞书自动化、Zapier、Make、n8n 或自写脚本。

### 8.3 模板侧需要准备

- 项目基础信息模板；
- Timeline 模板；
- 宣发文案 Prompt 模板；

## 10. 最小可行版本 MVP

建议 MVP 先做以下 5 件事：

1. **一张项目基础信息表**：统一填项目信息。
2. **一张 timeline 表**：按活动日期自动倒推提醒节点。
3. **一套宣发文案生成模板**：生成小红书、社群、朋友圈、Figma 文案。
4. **一套对接消息模板库**：嘉宾 / 选手消息按变量替换。
5. **一张任务分工表**：记录负责人、DDL、状态和提醒。

MVP 暂不做：

- 自动发布小红书；
- 自动发送微信消息；
- Figma 图层自动替换；
- 复杂权限系统；
- 完全自动分析所有聊天记录。

## 11. 推荐落地顺序

```text
第 1 步：把多维表格结构搭起来
第 2 步：补齐项目基础信息字段
第 3 步：沉淀 1 套标准 timeline
第 4 步：写 3-5 个高频文案 / 对接模板
第 5 步：用一个真实活动试跑
第 6 步：记录人工操作最麻烦的环节
第 7 步：再决定 API / 自动化开发优先级
```

## 12. 验收标准

第一版可用的判断标准：

- 新建一个项目后，可以自动或半自动生成 timeline；
- 到关键节点时，负责人能收到明确提醒；
- 至少能生成小红书、社群、朋友圈、Figma 四类宣发文案；
- 嘉宾 / 选手对接消息可以按模板替换变量；
- 任务分工能在表格里清楚看到负责人、DDL 和状态；
- 宣发负责人可以把确认后的文案交给设计排版；
- 项目结束后能回收发布链接、数据和复盘信息。

## 13. 风险与注意事项

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 自动化过早做太重 | 需求没稳定，开发返工 | 先做半自动 MVP |
| 文案质量不稳定 | 宣发效果受影响 | 保留人工审核环节 |
| Figma 模板不标准 | 难以自动替换图层 | 先统一图层命名 |
| 聊天记录隐私问题 | 数据安全风险 | 只读取授权内容，敏感信息脱敏 |
| 任务自动提取误判 | 错提醒 / 漏提醒 | AI 结果必须人工确认 |
| 多维表格字段变化频繁 | 自动化脚本容易失效 | 先稳定字段，再开发 API |
