# 个人工作台搭建模式调研

## 结论先行

**建议先走“Obsidian 导航页 / 首页工作台”作为第一版，而不是 WorkBuddy 或独立系统。**

理由：你的正式工作、项目记录和知识沉淀已经在 Obsidian 里；第一版最重要的是统一入口、减少跳转、把项目状态显性化，而不是立刻让 AI 或自动化接管。Obsidian 可以先用 Markdown + Wiki-link + Bookmarks + Canvas / Bases / Dataview 做一个低风险工作台；等信息架构稳定后，再决定是否接入 WorkBuddy、飞书多维表格、Notion、Dify 或自托管首页。

## 已验证事实

- WorkBuddy 官方定位是“全场景 AI 办公工作台”，覆盖办公、代码开发、设计创意，偏向通过自然语言让 AI 拆解并执行任务；它不是单纯的导航页工具。
- Obsidian 官方已有适合工作台的基础能力：
  - **Bookmarks**：可把文件、文件夹、搜索、标题、块、链接作为快捷入口。
  - **Canvas**：可在无限画布中摆放笔记、附件、网页并建立视觉关系。
  - **Bases**：核心插件，可对笔记属性进行类似数据库的查看、编辑、排序、过滤；适合项目、阅读、任务等清单型内容。
- Dataview 是社区插件，可把 Obsidian Vault 当作可查询的资料库，用查询语法自动生成列表、筛选和分组。
- B站上确实存在多类教程线索：Obsidian 导航页 / 主页、Obsidian Dataview、WorkBuddy 工作台、AI 工作台、自托管或知识库型工作台。但多数视频页面无法直接取得完整字幕，当前只把它们作为“教程线索”，不把视频内容当成已验证方案。

## 搭建模式对比

| 模式 | 搭建方式 | 适合解决什么问题 | 优点 | 风险 / 成本 | 对本项目判断 |
| --- | --- | --- | --- | --- | --- |
| Obsidian 导航页 / 首页 | Markdown 首页 + Wiki-link + Bookmarks + 搜索入口；可逐步加 Canvas、Bases、Dataview | 统一入口、项目状态、常用资料、任务清单、工作流路径 | 本地、低成本、和现有知识库一致、可逐步演进 | 动态能力依赖规范字段；复杂自动化有限 | **第一优先级，建议先做 MVP** |
| Obsidian Canvas 工作台 | 用 `.canvas` 做视觉地图，把项目、材料、问题、决策摆成图 | 适合视觉化理解项目、建立关系、回顾全局 | 直观、适合规划和复盘 | 不适合作为每日执行清单主入口 | 可作为首页旁边的“项目地图” |
| Obsidian Bases / Dataview 工作台 | 给项目、任务、资料加 frontmatter，再用 Bases 或 Dataview 自动生成看板/表格 | 进行中项目、待办、资料卡、状态跟踪 | 不离开 Vault；可随笔记更新自动刷新 | 要先统一字段；Dataview 是插件依赖 | 第二步，等字段最小化后加入 |
| WorkBuddy 型 AI 工作台 | 安装产品，用自然语言让 AI 执行办公、文档、代码或本地操作任务；可配 Skill | AI 代办、自动整理、文件处理、跨工具执行 | 上手快，适合演示“AI 帮我干活” | 权限、成本、账号、不可控执行、过度自动化 | **暂不作为底座**；可后续作为“助手层”实验 |
| Notion / 飞书多维表格 | 用数据库、视图、仪表盘、权限、协作搭建云端工作区 | 协作、项目管理、轻量业务系统、数据看板 | 视图和协作成熟；飞书适合业务表格 | 数据上云；与 Obsidian 分裂；迁移成本 | 如果未来要协作或统计，可作为外部模块 |
| 自托管首页：Homepage / Homarr / Homer / Heimdall | Docker / 服务器部署一个网页起始页，放服务入口和状态小组件 | 管理一堆网页服务、NAS、HomeLab、监控入口 | 视觉整洁，可作为浏览器首页 | 需要服务器/容器；主要是链接聚合，不是知识工作台 | 当前不优先，除非你有大量自托管服务 |
| Dify / RAG 知识助手 | 建知识库、检索节点、Chatflow/Workflow，让 AI 基于资料回答 | 对资料问答、SOP 助手、半自动流程 | AI 问答能力强，可扩展工具 | 需要维护知识库质量、检索评估、API 成本 | 不是首页；可在 Obsidian 结构稳定后再接 |
| 独立网页 / App | 用 Next.js/Vite/低代码等做定制页面，读取本地或云端数据 | 高定制化、统一视觉、跨系统聚合 | 可做成真正产品级入口 | 开发维护成本高；需要数据和权限设计 | 需求未定前不建议启动 |

## Obsidian 导航页第一版可以怎么做

### 首页只承担 5 个功能

1. **今天要进入哪里**：日常入口、收件箱、最近工作记录。
2. **现在有哪些项目**：进行中项目列表，而不是所有文件列表。
3. **每个项目下一步是什么**：只显示待确认、下一步、风险。
4. **常用资料和模板在哪里**：资料库、模板、规范、心法入口。
5. **AI 可以帮什么，不可以碰什么**：权限边界、可自动化任务、禁止接入数据。

### 建议页面结构草案

```markdown
# 个人工作台

## 今日入口
- [[00收件箱]]
- [[个人工作台工作记录]]
- 最近打开 / 最近推进：手动维护 3-5 条

## 进行中项目
- [[个人工作台项目总览]]
- 其他进行中项目入口

## 待确认
- 场景
- 数据边界
- 工具选型
- 验收标准

## 常用工作流
- 收集信息 -> 资料卡 -> 方案 -> 反馈 -> 工作记录
- 项目复盘 -> 可复用结论 -> 心法/模板

## 可让 AI 协助
- 调研总结
- 资料卡整理
- 链接检查
- 初稿生成

## 禁止自动化
- 未确认前接入账号
- 未确认前移动/删除文件
- 未确认前连接外部服务
```

### 字段最小集

如果后续要用 Bases / Dataview 自动汇总，建议先只统一这些字段，不要一开始设计太复杂：

```yaml
status: 需求确定 / 搜集信息 / 方案 / 反馈 / 进行中 / 暂停 / 完成
type: 项目 / 资料卡 / 工作记录 / 方案 / 决策
area: 个人工作台
next: 下一步动作
due: YYYY-MM-DD
updated: YYYY-MM-DD
```

## 当前建议

1. **先不采用 WorkBuddy 作为底座**：它适合做 AI 执行助手，但你的首要问题是“入口和结构”，不是“自动执行”。
2. **先做 Obsidian 首页导航 MVP**：只做一个 Markdown 导航页，不接外部账号、不装新服务、不改变现有目录结构。
3. **第二步再加动态汇总**：等你确认字段后，用 Obsidian Bases 或 Dataview 做“进行中项目 / 待确认 / 最近工作记录”的自动视图。
4. **第三步才评估外部工具**：如果以后需要团队协作或数据看板，再看飞书多维表格；如果需要 AI 问答，再看 Dify/RAG；如果需要网页服务入口，再看 Homepage/Homarr。

## 待确认问题

1. 这个工作台首先服务哪个场景：项目推进、学习、内容创作、日程任务，还是全局入口？
2. 你希望它是“每天打开的首页”，还是“某个项目的控制台”？
3. 你能接受社区插件 Dataview 吗，还是第一版只用 Obsidian 原生能力？
4. 是否允许把某些外部链接、账号入口、文件夹路径放进首页？
